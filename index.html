Web Page Refresh Recommendation System Using Logistic Regression

Author: Abdul Samad

Internship: FlyRank Machine Learning Internship 2026

Abstract

This project presents a prototype Web Page Refresh Recommendation System developed during the FlyRank Machine Learning Internship. The goal is to assist in identifying webpages that may benefit from content review by analyzing historical search-performance and user-engagement metrics. The project uses the anonymized FlyRank internship dataset obtained from the official Hugging Face repository. Because the dataset does not contain a ground-truth “needs refresh” label, a proxy target was defined for educational purposes. A Logistic Regression classifier was trained using selected Google Search Console and Google Analytics features. Model performance was evaluated using accuracy, precision, recall, F1-score, a confusion matrix, and a classification report. The project demonstrates a complete supervised machine learning workflow and highlights the importance of careful feature selection, proxy labels, and honest evaluation.

1. Introduction

Large websites often contain thousands of pages, making manual review difficult. Machine learning can help prioritize which pages should be reviewed first. This project demonstrates a simple and interpretable approach using Logistic Regression to classify pages as potential refresh candidates. The system is intended as a decision-support prototype rather than a production SEO system.

2. Problem Statement

The objective is to predict whether a webpage should be recommended for review using historical search and engagement data. The prediction has two classes: Refresh and No Refresh.

3. Dataset

The study uses the anonymized FlyRank internship dataset hosted on Hugging Face. Data includes Google Search Console and Google Analytics metrics such as impressions, clicks, average position, page views, sessions, engaged sessions, and scroll events. No client names, URLs, or private information were used.

4. Methodology

  • Load the official FlyRank dataset.
  • Inspect and preprocess the data.
  • Handle missing values.
  • Create a proxy target label named Needs_Refresh.
  • Select relevant features.
  • Split the dataset into training and testing sets.
  • Train a Logistic Regression model.
  • Evaluate model performance.
  • Generate refresh recommendations.

5. Features Used

  • Google Search Average Position
  • Google Analytics Page Views
  • Google Analytics Sessions
  • Google Analytics Engaged Sessions
  • Scroll Events

6. Model

Logistic Regression was selected because it is simple, interpretable, efficient for binary classification, and suitable for structured tabular data.

8. Discussion

The model generalized consistently because training and testing accuracy were similar. However, precision and F1-score remained modest because the target variable was a proxy label rather than an official annotation and the classes were imbalanced. These findings show both the usefulness and the limitations of applying supervised learning when a true target is unavailable.

9. Limitations

  • No official "Needs Refresh" label was available.
  • A proxy target was created for educational purposes.
  • The selected features may not capture every factor influencing content quality.
  • This system should be considered decision support rather than an automated SEO solution.

10. Conclusion

This project demonstrates a complete machine learning workflow using the FlyRank internship dataset. Logistic Regression was used to generate webpage refresh recommendations from search-performance features. Although the current prototype has limitations, it provides a practical foundation for future improvements using better labels, additional features, and alternative machine learning models.
